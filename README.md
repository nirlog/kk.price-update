# kk.price.update

Модуль для 1С-Битрикс с двумя изолированными режимами пересчёта каталожных цен.

## Режимы ценообразования

### Legacy Directory Pricing

Обычные directory-свойства продолжают использовать прежний алгоритм: модуль суммирует
`UF_PRICE` всех справочников товара и, при наличии SKU, рассчитывает предложения. Поведение
King-Komp и семантика существующих корректировок не изменены.

### KORSAC Default Pricing

Каноническое свойство `KK_*_DEFAULT` маршрутизируется отдельно. Для каждого выбранного типа
цены модуль получает `PricingPolicy` по паре `iblockId + priceTypeId`, читает
`ProductConfiguration` и передаёт расчёт `RetailOptionPriceProvider` и
`DefaultCatalogPriceCalculator` из `kk.korsac`. Полученный `DEFAULT_CATALOG_PRICE` является
готовой розничной ценой и записывается без локальной корректировки.

До создания файла ошибок и обработки товаров выполняется KORSAC preflight. Каждый явно
выбранный тип цены проверяется через Catalog API и
`KK\Korsac\Pricing\BitrixPricingPolicyProvider::get($iblockId, $priceTypeId)`. Идентичность
политики — строго `iblockId + priceTypeId`: сопоставление канала (`RETAIL`, `BUSINESS` и т. п.)
не требуется, потому что тип цены для массового обновления выбирает администратор. Повторы
ID удаляются с сохранением порядка, а отсутствующий тип цены или невалидная/отсутствующая
политика останавливают инициализацию до любых Catalog-записей.

`kk.korsac` является optional dependency: без него legacy-режим работает, а KORSAC-запрос
завершается ошибкой `korsac_module_not_available`. `KK_*_OPTIONS` и
`KK_*_MULTI_OPTIONS` **не обновляют base price**, скрыты в UI и отклоняются сервером. Их цены
используются конфигуратором как delta. KORSAC-товары с SKU намеренно отклоняются.

```text
                  Property Mode Resolver
                   /                  \
       Legacy Directory Pricing   KORSAC Default Pricing
                 |                         |
       existing directory sum       kk.korsac PricingPolicy
                                           |
                              DefaultCatalogPriceCalculator
                                           |
                                  DEFAULT_CATALOG_PRICE
```

## Что делает модуль

- Показывает в админке список каталогов (инфоблоков товаров).
- Позволяет выбрать directory-свойство товара и конкретные значения справочника (или все значения).
- Позволяет выбрать один или несколько типов цен. В Legacy-режиме индивидуальные
  `PRICE_ADJUSTMENTS` (`+1000`, `-2500`, `+20%`, `-10%`) работают как прежде. В
  KORSAC-режиме сохранённые или переданные `PRICE_ADJUSTMENTS` игнорируются: итог полностью
  определяет политика `kk.korsac` для `iblockId + priceTypeId`.
- Для каждого найденного товара:
  - находит все его свойства типа `directory`;
  - суммирует `UF_PRICE` выбранного значения + `UF_PRICE` остальных directory-свойств товара;
  - обновляет базовую цену товара (или цену его ТП, если есть предложения).
- Если у товара свойство `NO_PRICE_UPDATE` равно `N`, товар и его ТП **пропускаются**.
- Ведёт лог выполнения и сохраняет список ID товаров с ошибками в файл в `/upload/kk_price_update/`.
- Есть отдельная страница настроек по умолчанию, где можно сохранить для каждого каталога набор типов цен и их корректировки.

## Структура

- `admin/kk_price_update.php` — UI-страница модуля в админке.
- `admin/start_update.php` — AJAX-контроллер запуска обновления.
- `lib/Service/PriceUpdater.php` — основная бизнес-логика расчёта и обновления цен.
- `lib/Routing/PropertyModeResolver.php` — безопасная маршрутизация свойств.
- `lib/Pricing/` — KORSAC adapter и integer/minor-unit расчёты.

## Установка

1. Скопируйте модуль в директорию:
   - `/local/modules/kk.price.update`
2. Установите модуль в административной панели Битрикс:
   - **Marketplace → Установленные решения** (или через список модулей в вашей версии).
3. Убедитесь, что установлены модули:
   - `iblock`
   - `catalog`
   - `highloadblock`

Для KORSAC-режима дополнительно нужен `kk.korsac`; для установки и legacy-режима он не требуется.

## Подготовка данных

Перед запуском обновления:

1. У товаров должен быть хотя бы один property типа `directory`, связанный с HL-блоком.
2. В соответствующем HL-блоке у записей должно быть заполнено поле `UF_PRICE`.
3. (Опционально) Создайте у товара свойство `NO_PRICE_UPDATE`:
   - если значение этого свойства `N`, обновление для товара и его ТП выполняться не будет.

## Использование

1. Откройте страницу модуля в админке Битрикс.
2. Выберите каталог.
3. Выберите свойство типа «Справочник».
4. Выберите значения справочника (или оставьте «Все значения»).
5. Выберите один или несколько типов цен. Корректировка доступна только для Legacy; для
   KORSAC она отключена, поскольку цену определяет Pricing Policy.
6. Нажмите **«Обновить цены»**.
7. Дождитесь завершения и проверьте итоговую статистику:
   - сколько товаров/ТП обновлено;
   - сколько с ошибками;
   - сколько пропущено по `NO_PRICE_UPDATE`.

## Логи и ошибки

- Каталог логов: `/upload/kk_price_update/`
- Файл ошибок создаётся на каждый запуск и содержит ID товаров, обработанных с ошибками.
- Диагностики `kk.korsac` переносятся структурированно через безопасный список полей
  (`code`, группа, XML ID, свойство и контекст товара/инфоблока/типа цены). Произвольные
  сообщения, stack trace и внутренние данные исключаются.
- Административный лог форматирует безопасную диагностику по-русски, не скрывая исходный
  машинный код, например: `missing_option — группа CPU, значение AMD_OLD_ID`.
- Формат файла ошибок намеренно остаётся прежним — один ID товара на строку.

## Проверки

Domain-тесты не требуют Битрикс или PHPUnit:

```bash
php tests/Unit/run.php
```

Read-only smoke загружает настоящий `kk.korsac`, считает цену и выводит JSON, но ничего не
записывает в Catalog:

```bash
php local/modules/kk.price.update/tests/Integration/korsac_price_calculation_smoke.php \
  --iblock=2 --product=4 --price-type=2
```

## Важно

- KORSAC записывает явно выбранный Catalog price type. Флаг Bitrix `BASE=Y` не участвует
  ни в выборе политики, ни в выборе типа цены для записи.
- Модуль изменяет цены Catalog — рекомендуется сначала запускать на тестовом стенде.
- Для корректной работы пользователь должен иметь административные права и валидную сессию в админке.


## Настройки по умолчанию

- Страница: `Настройки по умолчанию` в меню модуля.
- Можно выбрать инфоблок (каталог), список типов цен и корректировки для каждого типа.
- Сохранённые значения автоматически подставляются на странице массового обновления при выборе каталога.
- Хранение настроек: в `Bitrix\Main\Config\Option` модуля (`default_price_settings`, JSON по ключу ID инфоблока).
- Сохранённые корректировки не удаляются при работе в KORSAC-режиме и снова применяются при
  выборе Legacy-свойства.
